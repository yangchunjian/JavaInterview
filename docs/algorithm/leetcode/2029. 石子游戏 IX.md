## 题目

Alice 和 Bob 再次设计了一款新的石子游戏。现有一行 **n** 个石子，每个石子都有一个关联的数字表示它的价值。给你一个整数数组 `stones`，其中 `stones[i]` 是第 **i** 个石子的价值。

Alice 和 Bob 轮流进行自己的回合，**Alice 先手**。每一回合，玩家需要从 `stones` 中移除任一石子。

- 如果玩家移除石子后，导致**所有已移除石子**的价值**总和**可以被 **3** 整除，那么该玩家就**输掉游戏**。
- 如果不满足上一条，且移除后没有任何剩余的石子，那么 **Bob** 将会直接获胜（即便是在 Alice 的回合）。

假设两位玩家均采用**最佳**决策。如果 Alice 获胜，返回 `true`；如果 Bob 获胜，返回 `false`。

### 示例 1

| 项目 | 内容 |
| --- | --- |
| **输入** | `stones = [2,1]` |
| **输出** | `true` |
| **解释** | 回合 1：Alice 移除任意一个石子；回合 2：Bob 移除剩下的石子。已移除石子总和为 1 + 2 = 3，可被 3 整除，Bob 输，Alice 获胜。 |

### 示例 2

| 项目 | 内容 |
| --- | --- |
| **输入** | `stones = [2]` |
| **输出** | `false` |
| **解释** | Alice 移除唯一石子后总和为 2，无法被 3 整除，且石子已取完，Bob 获胜。 |

### 示例 3

| 项目 | 内容 |
| --- | --- |
| **输入** | `stones = [5,1,2,4,3]` |
| **输出** | `false` |
| **解释** | Bob 总会获胜。一种走法：Alice 取 1（总和 1）→ Bob 取 3（总和 4）→ Alice 取 4（总和 8）→ Bob 取 2（总和 10）→ Alice 取 5（总和 15，可被 3 整除），Alice 输。 |

### 提示

- `1 <= stones.length <= 10^5`
- `1 <= stones[i] <= 10^4`

## 思路

胜负只与**已移除石子价值总和能否被 3 整除**有关，因此只需关心每个石子价值除以 3 的**余数**（0、1、2），不必关心具体数值。

**第一步：统计余数个数**

遍历 `stones`，用长度为 3 的数组 `cnt` 记录余数为 0、1、2 的石子个数。

**第二步：首手约束**

Alice 先手。若她先取余数为 0 的石子，移除后总和为 0，可被 3 整除，立即判负。因此首手只能取余数为 1 或余数为 2 的石子，需分别讨论两种开局。

**第三步：模拟一种开局（check）**

假设 Alice 首手取一个余数为 1 的石子（`cnt[1]` 减 1）。此后：

- 余数为 0 的石子不改变总和对 3 的余数，双方可在任意回合取走，只影响**回合数**的奇偶。
- 余数为 1 与 2 的石子会改变余数，双方会尽量按 1、2 交替取，形成固定节奏。

在双方最优下，可先让 1 与 2 各取 `min(cnt[1], cnt[2])` 对（每对占 2 回合），再加上全部余数为 0 的石子，得到这一段的总回合数 `r`。若余数为 1 的石子仍比余数为 2 的多，Alice 还能多取一个余数为 1 的石子，`r` 再加 1。

Alice 能赢当且仅当：这段结束后**总回合数为奇数**（轮到 Bob 取子且被迫让总和被 3 整除），且余数为 1 与 2 的剩余个数**不相等**（否则 Bob 有应对空间）。

**第四步：两种首手合并**

将 `cnt` 中余数为 1 与 2 的计数对调，等价于讨论 Alice 首手取余数为 2 的情况。答案为两种开局模拟结果的**或**：`check(c1) || check(c2)`。

时间复杂度 O(n)，额外空间 O(1)。

## 解法

```java
class Solution {
    public boolean stoneGameIX(int[] stones) {
        int[] c1 = new int[3];
        for (int x : stones) {
            c1[x % 3]++;
        }
        int[] c2 = {c1[0], c1[2], c1[1]};
        return check(c1) || check(c2);
    }

    private boolean check(int[] cnt) {
        if (--cnt[1] < 0) {
            return false;
        }
        int r = 1 + Math.min(cnt[1], cnt[2]) * 2 + cnt[0];
        if (cnt[1] > cnt[2]) {
            --cnt[1];
            ++r;
        }
        return r % 2 == 1 && cnt[1] != cnt[2];
    }
}
```

## 总结

- 只按价值对 3 的余数分类，首手不能取余数为 0 的石子。
- 余数为 0 的石子不改变总和余数，主要影响回合奇偶。
- 分别模拟 Alice 首手取余数 1 或 2，任一开局能使 Alice 获胜则返回 `true`。
